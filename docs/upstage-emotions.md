# Upstage 감정 후보 API — 첫 연결

작업 브랜치: `feature/upstage-emotions`

## 구현 범위

로그인한 사용자의 텍스트를 받아 Upstage에 한 번 요청하고, 짧은 공감과 감정 후보 2~3개를 반환한다.
후보는 확정된 감정이 아니다. 이 API는 선택 결과, 원문, 응답을 DB·파일·캐시·세션에 저장하지 않는다.
요청 DTO와 응답 DTO의 `toString()`에서도 내용을 숨긴다. 외부 오류 본문이나 예외 원인은 로그로 전달하지 않는다.

STT, 위험 단계 판정, 사용자 선택 저장, 진정, 욕구 확인, 3인칭 정리, 만약–그러면 계획은 이번 범위에 없다.
프롬프트의 행동 지침은 별도 위험 대응 기능이나 효과 검증을 대신하지 않는다.

## 로컬 API 키 등록

실제 키를 채팅, Git, `.env.example`, `application-local.yml.example`에 적지 않는다.

방법 1 — IntelliJ 실행 구성:

1. `실행 → 구성 편집`에서 `ToroApplication` 선택.
2. 환경 변수에 `UPSTAGE_API_KEY`를 추가하고 본인의 키를 값으로 입력.
3. 필요하면 `UPSTAGE_MODEL`을 추가. 기본값은 `solar-pro4`.
4. 실행 구성을 공유 파일로 저장하지 않고 서버를 다시 실행.

방법 2 — 이미 Git에서 제외된 `src/main/resources/application-local.yml` 끝에 추가:

```yaml
upstage:
  api-key: "여기에 본인의 키 입력"
```

두 방법 중 하나만 사용한다. `.env`는 Spring이 자동으로 읽지 않는다.
키가 없어도 회원·캐릭터 API는 실행되며, 감정 API만 `AI_001`을 반환한다.
대회 계정에서 이용 가능한 모델과 크레딧 적용 여부는 본인 콘솔에서 확인해야 한다.

## 요청·응답

`POST /api/v1/vent/emotions`

- 기존 로그인 응답의 JWT 필요: `Authorization: Bearer <accessToken>`
- 본문: `Content-Type: application/json`
- 앞뒤 공백 제거 후 1~2000자.

```json
{
  "text": "친구가 약속을 계속 미뤄서 내 시간이 존중받지 못한 것 같아요."
}
```

성공 예시(실제 모델 결과는 달라짐):

```json
{
  "success": true,
  "data": {
    "empathy": "약속이 계속 미뤄지면 서운하고 답답할 수 있겠어요.",
    "candidates": ["서운함", "답답함", "실망감"],
    "canSkip": true
  },
  "error": null
}
```

`Cache-Control: no-store`. `canSkip`은 항상 `true`이며 감정 확정을 요구하지 않는다.
AI 결과는 일반 텍스트로 렌더링하고 HTML로 삽입하지 않는다.

| HTTP | 오류 코드 | 의미 |
| --- | --- | --- |
| 401 | COMMON_002 | 미로그인·만료·탈퇴한 계정 |
| 400 | COMMON_001 | 빈 입력·2000자 초과 등 요청 검증 실패 |
| 503 | AI_001 | API 키 미설정 |
| 502 | AI_002 | 외부 인증 오류·네트워크 오류·타임아웃 등 |
| 502 | AI_003 | JSON 오류·후보 개수/형식 오류·잘린 응답 등 |
| 503 | AI_004 | Upstage의 요청 제한(429) |

AI 오류 코드는 신규 초안이다. 팀의 노션 명세에 공유 후 확정한다.

## 프론트 연결 기준

- 후보 확인·수정·해당 없음, 직접 입력, 아직 모르겠어요, 후보 다시 보기를 제공한다.
- 아무 후보도 선택하지 않아도 진행한다. API 실패 시에도 직접 입력·건너뛰기를 제공한다.
- 후보 다시 보기는 같은 API에 다시 요청한다. 새로운 후보가 반드시 나온다는 보장은 없다.
- 요청 중 버튼을 비활성화해 중복 호출을 줄인다. 성공 응답의 도착 순서가 바뀌지 않도록 이전 요청을 관리한다.
- 정리 단계에는 사용자가 확정한 감정 단어 또는 빈 값만 넘긴다. 이 응답 전체나 원문을 넘기지 않는다.
- 경계에서 원문·음성·STT 결과·공감 응답·미선택 후보를 비우는 프론트와 전체 세션 처리는 별도 구현 대상이다.
- 서버는 요청 동안 메모리에서 처리한다. JVM 메모리의 즉시 물리적 삭제나 외부 사업자의 삭제 완료를 확인하는 기능은 아니다.

## 사용량·외부 정책

- 한 번 요청할 때 외부 호출은 한 번. 자동 재시도 없음.
- 생성 토큰 상한 1024, 연결 제한 5초, 응답 읽기 제한 30초.
- 타임아웃·사용자 화면 이탈 후에도 외부에서 처리가 완료되어 사용량이 발생할 수 있다.
- 사용자별 요청 횟수 제한과 예산 차단은 아직 없다. 공개 배포 전에 별도 설계가 필요하다.
- Upstage 공식 시작 안내에는 API 데이터를 저장하거나 재사용하지 않는다고 설명되어 있다.
  대회 계정의 계약·보관 예외·로그 정책까지 검증한 것은 아니므로 서비스 전체의 삭제 보장을 약속하지 않는다.

## 검증 방법

```bash
./gradlew test
```

모의 HTTP 응답으로 외부 요청 형식, 성공 파싱, 잘못된 JSON/후보, 중복 후보, 출력 크기 제한,
응답 중단, 공급자 오류, 타임아웃, 키 누락을 검증한다.
MVC 테스트에서는 실제 프로젝트의 JWT 인증 필터와 공통 오류 처리를 사용한다.
모의 테스트는 외부 API나 크레딧을 사용하지 않으며 실제 모델의 공감 품질은 검증하지 않는다.

실제 키 등록 후 Swagger의 `4. 감정 후보`에서 합성 예문 1건으로 확인한다.
기존 회원가입 → 로그인 → Authorize(토큰만 입력) → 감정 후보 제안 순서다.
